Instructions

  1. Select a file from your computer using the file selector.
  2. Click Register Original File to save its hash as the baseline.
  3. To check if the file is modified, select it again (same or edited version).
  4. Click Verify File to compare the current hash with the baseline.
  5. See the result displayed below: INTACT means unchanged, TAMPERING DETECTED means mismatch.
  6. Use Reset to clear all data and start fresh.

Note on data storage: Baseline hashes are saved locally in your browser's storage. This means they persist as long as you don't clear browser data, but can be cleared at any time. The file contents never leave your computer.

Project Overview

This File Tampering Detection System is designed to detect unauthorized modifications to files by comparing SHA-256 hashes.

Abstract

The project implements a secure, client-side method to establish a trusted baseline for a file's content and later verify if the file has been tampered with by recalculating and comparing cryptographic hashes.

Objectives

  • To detect unauthorized file changes quickly and reliably.
  • To educate users on cryptographic hashing and file integrity verification.
  • To build a user-friendly, secure web application tool adhering to data privacy principles.

Methodology

The system uses the SHA-256 hashing algorithm implemented via the Web Crypto API to produce unique digital fingerprints for files. Users register an original file hash locally, then verify any later version by comparing hashes. Matching hashes confirm file integrity; differences indicate tampering.

Algorithm

  1. User selects a file.
  2. Compute SHA-256 hash of the file's contents.
  3. Register the hash as the baseline and save it locally.
  4. On verification, compute the current hash again.
  5. Compare current hash with baseline.
  6. If equal, show "INTACT"; if not, show "TAMPERING DETECTED".

Modules

  • File Selection and Upload Interface
  • SHA-256 Hash Calculation Using Web Crypto API
  • Local Storage Management for Baseline Hashes
  • Result Display and User Feedback
  • Error Handling and User Guidance
  • Information Section Explaining Project Details

Test Cases

  • Register a text file (e.g., notes.txt), verify it unchanged → result should be INTACT.
  • Modify the text file (add some text), verify again → result should be TAMPERING DETECTED.
  • Try to verify without registering → error message about missing baseline.
  • Upload unsupported or empty files → appropriate errors or messages.
  • Reset function clears saved data and GUI states.

Limitations

  • Saved baseline hashes rely on browser local storage, which can be cleared.
  • Local storage is accessible to users and other scripts running on the same origin — not fully secure against a determined attacker.
  • Does not protect against file replacements at the operating system level outside this app.
  • Does not support multiple files simultaneously.

Conclusion

This system provides a basic, secure way to detect file tampering on the client side without exposing file content to servers. It educates users about cryptographic integrity checks and highlights browser storage security considerations.

Security Notes and Recommendations

Baseline hashes stored locally are vulnerable if an attacker gains access to browser data or modifies it in the same storage environment. For stronger security in real scenarios:

  • Use secure, tamper-proof external hardware storage or secure enclave technologies.
  • Combine hash storage with digital signatures and trusted timestamping from a secure server.
  • Implement user authentication and encrypted databases for hash management.
  • Use dedicated integrity monitoring software at the system or application level.
